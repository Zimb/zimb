## 1. Context and Project Overview

### 1.1 Brand Identity

| Item | Value |
|---|---|
| **Name** | Zimb |
| **Primary Domain** | `zimb.app` |
| **Subdomains** | `app.zimb.app` (Flutter Web seniors), `api.zimb.app` (middleware) |
| **Status** | Scoping phase (pre-MVP) |
| **Founders** | Zimb core team (3 people) |
| **Contact** | `contact@zimb.app` |

Zimb is a **debugging-as-a-service** marketplace tailored for developers writing software with generative AI assistance.

### 1.2 Problem Statement

**Field Observations:**

- The rise of "Vibe Coders" (junior developers relying heavily on Cursor, Copilot, Cline, Windsurf) generates a high volume of bugs **unresolvable by AI alone**: CORS errors, race conditions, complex environment setup, circular dependencies, and edge cases.
- These developers are **blocked** in a loop between AI hallucination/deadlocks and hiring senior freelancers (which is expensive, slow, and unsuitable for rapid micro-debugging).
- Qualified senior developers **waste time** prospecting for long contracts when they could monetize spare capacity resolving 5 to 10 micro-bugs daily.

**Market Opportunity:** A **rapid bounty model (45-minute SLA)** backed by Stripe pre-authorization and integrated peer arbitration.

### 1.3 Target Objectives

| # | Objective | Target KPI (6 months) |
|---|---|---|
| **O1** | Launch functional MVP across 3 channels (web, VS Code extension, senior app) | Uptime >= 99% |
| **O2** | Reach product-market fit on Vibe Coder demographic | >= 100 validated tickets / month |
| **O3** | Build active pool of 50 senior engineers | >= 30% monthly retention |
| **O4** | Guarantee financial security (Stripe escrow) | 0 lost funds incidents |
| **O5** | Achieve unit economic profitability (20% commission) | GMV >= 5,000 EUR / month |

### 1.4 Out of Scope (Won't Have — V1)

- Native mobile applications (iOS/Android) — deferred to V2.
- Multi-language localization — English and French only for V1.
- Public reputation system with user reviews.
- Direct integration with alternative IDEs (JetBrains, Sublime) — VS Code only for V1.

## 2. Scope and Features

### 2.1 User Personas

| **Zimb Admin** | Internal operations | Internal admin dashboard | Oversee operational health and SLA escalations |

### 2.2 Core User Stories

#### Vibe Coder

- *As a* **Vibe Coder**, *I want to* submit a ticket via `@zimb` inside VS Code Copilot with pre-filled context, *so that* I can document a bug in under 30 seconds.
- *As a* **Vibe Coder**, *I want to* pre-authorize payment via credit card, *so that* senior engineers have guaranteed compensation upon delivery.
- *As a* **Vibe Coder**, *I want to* click **"Quick Win!"** immediately upon verification, *so that* payment is released instantly to the senior.
- *As a* **Vibe Coder**, *I want to* initiate a dispute if work is incomplete or defective, *so that* my escrowed funds are safeguarded.

#### Senior Engineer

- *As a* **Senior**, *I want to* browse available tickets styled as urgency-colored notes, *so that* I can quickly identify high-priority issues.
- *As a* **Senior**, *I want to* claim a ticket with one action, *so that* I lock a 45-minute exclusive resolution window.
- *As a* **Senior**, *I want to* receive automatic collaborator access to the private repository, *so that* I can inspect code immediately.
- *As a* **Senior**, *I want to* receive real-time notifications when another developer claims a ticket ("Match!"), *so that* I do not duplicate effort.
- *As a* **Senior**, *I want to* receive payouts within 7 days of validation, *so that* my income remains predictable.

#### Reviewer

- *As a* **Reviewer**, *I want to* inspect disputed tickets with GitHub diffs and ticket descriptions, *so that* I can issue a binding verdict within 48 hours.
- *As a* **Reviewer**, *I want to* collect the 20% platform fee when resolving an arbitration in favor of the requester, *so that* my review time is compensated.

## 3. Technical Specifications and Constraints

### 3.1 Target Architecture

| Component | Technology | Rationale |
|---|---|---|
| Landing (`zimb.app`) | Astro or Next.js (Static) | SEO optimization, fast edge delivery |
| Senior App (`app.zimb.app`) | Flutter Web | Founder specification |
| Middleware (`api.zimb.app`) | Cloudflare Workers (TypeScript, Hono or Itty Router) | Edge latency, cost-free tier under 100k requests/day |
| Data Store | Airtable | Rapid relational prototyping for MVP |
| Payments | Stripe Connect (Express Accounts) | Escrow hold and automated split disbursement |
| GitHub Operations | GitHub App (`@zimb-bot`) | Programmatic collaborator invitations and access control |
| Scheduled Tasks | Cloudflare Cron Triggers | Serverless automated execution |
| Real-time Updates | Native WebSockets (Cloudflare Durable Objects) | Live state synchronization across Kanban clients |
| Authentication | GitHub OAuth | Aligned with target developer audience |
| Transactional Email | Resend or Postmark | High deliverability to developers |
| Analytics | Plausible Analytics | Privacy-first analytics without cookie banners |

### 3.3 Third-Party Integrations

| Service | Type | Role | Authentication |
|---|---|---|---|
| **Airtable** | REST API | Primary database (tickets, users, claims, ledger) | Personal Access Token (PAT) |
| **Stripe Connect** | REST + Webhooks | PaymentIntents, pre-auth capture, transfers, Express onboarding | Secret Key + Webhook Signing Secret |
| **GitHub** | REST + GraphQL | Repository creation, branch creation, collaborator invites and revocations | GitHub App Private Key (RS256) |
| **Resend / Postmark** | REST | Transactional notification emails | API Key |
| **Plausible** | JavaScript | Anonymous analytics | Domain configuration |

### 3.4 Core API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/tickets` | Create a new ticket (channel: `web` or `vscode`) |
| `GET` | `/tickets` | Paginated ticket listing with filters |
| `POST` | `/tickets/:id/claim` | Atomic claim with concurrency lock |
| `POST` | `/tickets/:id/deliver` | Mark ticket as delivered by senior |
| `POST` | `/tickets/:id/validate` | "Quick Win!" validation (triggers capture and payout) |
| `POST` | `/tickets/:id/dispute` | Initiate dispute |
| `POST` | `/tickets/:id/review` | Arbiter decision submission |
| `GET` | `/me/tickets` | Retrieve current senior tickets |
| `GET` | `/track/:ticketId` | Public status check for requester |
| `POST` | `/webhooks/stripe` | Stripe event ingestion |
| `POST` | `/webhooks/github` | GitHub webhook ingestion |

### 3.5 Security and Compliance

#### Authentication and Access Control
- **Seniors**: GitHub OAuth flow producing signed HS256 JWT tokens with a 7-day TTL and refresh mechanisms.
- **Requesters**: Passwordless email magic links (Resend) issuing JWT tokens scoped with `role: client`, restricted to their own tickets.
- **Reviewers**: Strict role enforcement requiring `role: reviewer` on the `/tickets/:id/review` endpoint.

#### Privacy and Data Protection (GDPR)
- Minimize collected personal data: email address and GitHub handle only.
- No third-party tracking scripts beyond privacy-compliant Plausible Analytics.
- Right to erasure: `DELETE /me` endpoint purges Airtable records and closes associated Stripe Connect accounts.
- Audit logs retained for a maximum of 12 months.

#### Performance Benchmarks
- Time-to-Interactive (TTI) on `zimb.app`: < 1.5 seconds (P75).
- Latency on `POST /tickets`: < 300 ms (P95).
- Real-time WebSocket broadcast latency: < 200 ms (P95).
- Infrastructure availability: >= 99.5% excluding scheduled maintenance.

#### GitHub Security Policies
- `@zimb-bot` maintains exclusive authority over repository access management on `zimb-*` repositories.
- Zero permanent administrative credentials for staff in production environments.
- Maintain immutable access audit logs for 24 months.

### 3.6 Financial Invariants
- Minimum bounty amount: 10 EUR.
- Maximum bounty amount: 500 EUR (higher amounts require custom agreements).
- Zimb platform fee: Fixed 20% on all settled bounties.
- Stripe pre-authorization duration: 7-day lifespan, enforcing a dispute SLA <= 48 hours.
- Payout execution: Capture and disbursement executed within 24 hours of ticket validation.

### 5.4 MVP Acceptance Checklist

The MVP is complete when all of the following criteria are met:

- [ ] Requester can submit a ticket through `zimb.app/submit` and through `@zimb` inside VS Code.
- [ ] Payment is pre-authorized in escrow without premature capture until resolution.
- [ ] Authenticated senior engineer can view, claim, and work a ticket within 45 minutes.
- [ ] Claimed tickets immediately become invisible on the public Kanban board to other seniors.
- [ ] Real-time "Match!" websocket events reach other connected clients within 1 second.
- [ ] Dedicated private GitHub repository is created and the senior is automatically invited upon claim.
- [ ] "Quick Win!" action captures payment, transfers 80% to senior, and revokes GitHub access.
- [ ] 24-hour auto-validation executes if requester does not respond following delivery.
- [ ] Disputes are routed and resolved within the 48-hour SLA.
- [ ] Financial loss rate is 0 throughout the pilot.

### B. Terminology Glossary

- **Vibe Coder**: Junior developer leveraging generative AI coding assistants (Cursor, Copilot, Windsurf).
- **Bounty**: Monetary incentive established by requester for resolving a bug.
- **Lock and Timer**: Exclusive 45-minute reservation granted to a claiming senior.
- **Quick Win!**: Manual instant payment approval by requester.
- **Match!**: Real-time push notification indicating a ticket has been claimed.
- **Reviewer**: Qualified senior engineer responsible for arbitrating disputed resolutions.
- **Channel**: Ingestion source of the issue (`web` or `vscode`).
